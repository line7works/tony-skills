# Vertical

The final inspection before a build is called done. `/signoff` inspects one slice; `/vertical` inspects the whole structure once every slice's card stands `signed off` — Claude reviewing the entire vertical against its base, joined (on Tony's per-run word) by outside reviewers with a mandate to reject it. Every reviewer, local or outside, is a call on `/readers`, the loop's reader component (`readers-protocol: 1`; every request this skill sends carries `protocol_version: 1`): the model ids, efforts, windows, budgets, sandboxes, no-web parity lines, and transports live in readers' roster, this skill pins none of them, and a roster row moves only by PR on Tony's word, never mid-run. One verdict doc comes out. Nothing gets fixed here.

**The spine.** /signoff's doctrine governs every finding in this skill — the finding shape (claim · `file:line` · concrete failure scenario · severity BLOCKER/MAJOR/MINOR · confidence), verify-before-reporting (CONFIRMED/PLAUSIBLE, `Refuted: N`), the severity → verdict mapping, and report-don't-repair. /vertical adds only the whole-build scope, the outside reviewers, and the merge. Where this file is silent on review mechanics, /signoff's SKILL.md is the law.

**The one unforgivable move is an unverified outside finding reaching the verdict.** Outside models hallucinate file paths and invent plausible defects. Every outside finding is adversarially verified against the source before it can land in the verdict section; what fails verification is dropped from the verdict, counted, and left visible only in the raw appendix.

## Step 1 — Gate

**The repo's inspection sheet, first.** Read `<repo>/REVIEW.md` before the doc hunt and the gate. It is the sheet only under /signoff's test (the three headings, every pass line `on` or `off`); a file of that name that fails it is reported as `present but not the kit sheet — defaults` and ignored. Present and well-formed, it governs the local review exactly as it governs /signoff (whose Step 1 states the rule): a pass under `## Passes` marked `off` is skipped and the verdict doc names the skip with the reason on that line; the `## Severity bar` is the severity mapping for every finding this run grades, outside findings included, overriding /signoff's table where they differ; and each `## Repo-specific checks` line is an item the local reviewers must try to break, listed by name in the verdict doc's section 1 as held or as the finding it became. Absent, the run uses /signoff's defaults and the chat block's `REVIEW.md:` line says `absent — defaults`. Outside reviewers never see it: its `## Repo-specific checks` are distilled from prior verdicts, so the file is excluded from the export beside `docs/reviews/` (Step 3) and the packet adds nothing for it — the local review alone honours the sheet, and its verdict carries the checks for both. /vertical never writes `REVIEW.md` (rule 7).

The invocation names a build doc, or the skill hunts the current repo per /build's Step 1 doc tiers (`docs/plans/*.md` — the repo doc kit's folder — then the older flat `docs/<feature>-build-plan.md`, both read before choosing: a candidate matches the invocation by filename, the `<topic>` of a `YYYY-MM-DD-<topic>.md` name or the `<feature>` of a flat name; an `Intent:` line is consulted only when no filename in either matches; a filename match beats an Intent-line match; when both match by filename `docs/plans/` wins and the verdict says which it took; several plausible matches are listed and asked; then any phase/slice doc under `docs/` or `plan/`) or takes the plan established in this session — /ship's two-source narrowing: nowhere else, no wider hunt; unresolvable means ask Tony.

Read every `## Slice` heading's `Status:` line in the build doc. A doc with zero `## Slice` headings, or a slice heading missing its `Status:` line, is malformed input: report it and STOP — the gate never passes vacuously. The gate passes only when **every slice stands `signed off`** — the loop's terminal clean state. Anything less — `built`, `signed off with conditions`, `rejected`, `not started` — fails the gate: report exactly which slices are short and in what state, and STOP. (A `built` card's remedy is a fresh /signoff, never /recheck — say so when naming it.)

Two more preconditions run with the gate, before any ask:

- **The reviewed repo must be a git repo.** No git means no base, no export, no boundary — report that /vertical cannot run here and STOP.
- **The working tree must be clean where the review looks** (`git status --porcelain`, checked against the change boundary and the build doc). Dirt that touches a boundary file or the build doc means the review would grade stale code: report it and STOP; Tony decides whether to commit first or order a committed-state-only run, and that order is recorded in the Method line. Dirt entirely outside the boundary and the build doc (a perpetually-dirty feedback log, unrelated untracked docs) does not stop the run: the review proceeds against committed state (HEAD) on both legs, and the unrelated dirt is listed in the Method line. (Scoped from an any-dirt stop 2026-08-21, per Tony, after the first live Atlas run stopped on unrelated docs.)

Only wording in Tony's own invocation ("run it anyway") collapses the gate. The skill never proposes it, and a collapsed gate is recorded in the verdict doc's Method line. The gate and preconditions run BEFORE the reviewer ask — no picking a crew for a run that stops.

## Step 2 — The ask

Before the ask, every run: mint a FRESH run id for this run — one path segment, characters `[A-Za-z0-9._-]` only (readers refuses anything else as `invalid-request`), e.g. `vertical-<YYYYMMDD>-<four hex>` — and make the run directory (`mktemp -d`, a scratch path outside any repo; Step 3 fills it). Then two summons of `suggest` under this run id, in this order: first `/readers suggest claude-session --run <run id> --run-dir <run dir>/readers --floor opus` (the local row alone, under /signoff's floor, which is what the local calls carry in Step 4: a typed id is never classified against a floor, so a remembered typed pick on `claude-session` is dropped here with a drop note instead of refusing every local call as `unknown-model` after the ask; this first call freezes the run with that drop in its snapshot), then `/readers suggest gpt-astra,gpt-sol,gemini,deepseek,qwen --run <run id> --run-dir <run dir>/readers` (the outside rows, no floor, because Step 4's outside calls carry none: their remembered picks stay and are shown; a floor on this call would drop them and write the drop into the memory every skill shares). Together they cover every row the ask can offer, so the ask shows what will actually run (the model the ask shows is the model that sends); the order is load-bearing — the outside rows first would freeze the run before the local drop, and every local call would then be `unknown-model`. Then stop and ask:

> Local-only review, or local + outside reviewers? (Recommended: local + GPT + Gemini. Outside reviewers see the full tracked code.)

beneath it, one line per row with the model `suggest` showed, any drop note, and the profile the row runs under (Step 4):

- **local** — always runs; row `claude-session`, this session's own model (name the id the session reports for itself — `suggest` shows the placeholder `session` for this row), profile `repo-with-tools` under signoff's floor. Needs no word.
- **GPT** — row `gpt-astra` (the default GPT row) or `gpt-sol`, profile `repo` on the export; a different GPT model is an id Tony types against one of these rows (passed as that request's `model`), never another row.
- **Gemini** — row `gemini`, profile `repo` on the export.
- **DeepSeek** — row `deepseek`, profile `packet-only` (the export's documents travel in the prompt; the row has no filesystem).
- **Qwen** — row `qwen`, profile `packet-only`, the same.

The skill **always waits for an answer** — silence never proceeds, and the recommended default is a recommendation, not a trigger. Tony may answer with any subset ("local + GPT only", "local + DeepSeek + Qwen" are legal); an answer must name the row (a bare "outside" or "both" re-asks). The answer applies to this run only; nothing is remembered between runs. Every external send in this skill is authorized by this answer in this run and nothing else: `authorized: true` goes on exactly the outside calls his answer named, never on the local calls, never inferred, never carried over from another run. A row `suggest` reported unavailable is offered as dropped-with-reason and never sent. No outside call is ever re-sent under this run id, and no call id is ever reused (a call id is single-use; Step 4's one local re-send takes a fresh id); a rerun of the review is a fresh Step 1–7 run with a fresh run id and its own `suggest`.

## Step 3 — The base and the packet

Determine the base — the build's starting commit — by this precedence: (1) a base commit the build doc records, if any; (2) the branch point from the default branch (`git merge-base`); (3) neither resolvable → ask Tony for the base, never guess. Record the base and how it was determined; both go in the Method line.

When outside reviewers are on, compose the cold packet. Each outside reviewer receives exactly three things:

1. The build doc, verbatim — the spec they grade against.
2. The full tracked code, via a **tracked-files-only export**: `git archive` the reviewed state into `<run dir>/export/` (a fresh directory, never reused), with `docs/reviews/` and `REVIEW.md` excluded from the export (`git archive <ref> . ':!docs/reviews' ':!REVIEW.md'`) — that folder holds the per-slice signoff verdicts and this skill's own earlier verdicts, the sheet's repo-specific checks are distilled from them, and the next rule keeps all of it out of the packet. Never point an outside tool at the live working tree. This is a hard rule with a reason: untracked files, gitignored files, `.env`, and credential files must be *physically absent* from what outside models can read, not merely unmentioned.
3. The change boundary: the base commit id and the list of files the vertical touched (`git diff --name-status <base>..HEAD`), so they know new construction from the existing house.

Never in the packet: per-slice signoff verdicts (the `docs/reviews/` folder, excluded from the export above), `REVIEW.md` (excluded the same way), punch-list history, chat context, or another reviewer's output. The reviewers go in cold on findings — that is the point of paying for outside eyes.

The prompt is composed from `assets/vertical-mandate.md`: fill its placeholders with the build doc and the boundary and write it to `<run dir>/mandate.md`, the `mandate` every outside request names by path. The code reaches a `repo` row as its `workspace` (the export directory) and a `packet-only` row as its `documents`: for each packet-only row Tony named, stage the export's UTF-8 text files into `<run dir>/packet-<row>/`, one file per export file named by its export-relative path with every `/` replaced by `__` (so the prompt's `DOCUMENT` labels carry the path and a reviewer's citation maps back to `file:line` at the merge; a bare basename would collide across the tree), and list every staged file as that request's `documents`. A file that does not decode as UTF-8 (an image, audio) is left out of the packet and named in the Method line; readers refuses an undecodable document as `invalid-request`, so it never travels. Never in a packet or a workspace: the live working tree. The local review's workspace is cut here too: `git worktree add --detach <run dir>/worktree <head>` (the same reviewed commit the export was cut from, so both legs review one code state and :25's unrelated dirt reaches neither), removed with `git worktree remove --force <run dir>/worktree` and `git worktree prune` after Step 5 — worktree metadata under `.git/` is the only trace, and it is gone before the verdict is written.

## Step 4 — The reviews

Every reviewer is one `/readers` call under this run's id, in two summons in sequence: the local fleet first, then — only after Step 5's local merge and verification are written down — the outside fleet of the reviewers Tony named (readers' report hands back every call's `raw_text` in one message, so one combined fleet would put outside text in front of the session before the local verdict formed; two summons under the one run id keep the order, and the snapshot frozen at Step 2 covers both). Within a summon the calls launch together (readers runs the portable rows in the background and the host rows through their tools in one message), each with ZERO shared context: a reviewer receives the prompt readers composes from its request — the mandate and the documents, plus readers' fixed reader instruction on the Claude row — never chat history, never another reviewer's output. Every request carries `protocol_version: 1`, `run_id` this run's, `run_dir` `<run dir>/readers`, a single-use `call_id` under this run's id, and no `raw_path` (the verdict doc is this skill's one write, rule 7, and its appendix carries each reviewer's text; the runner's `raw.md`, sidecar, and diagnostics under `<run dir>/readers/<call id>/` are the evidence and are never edited).

**Local, always.** The local review runs at vertical scope — the whole vertical against its base — under /signoff's full reviewer mechanics: **fresh subagent reviewers originate the findings, never this session solo** (the session merges, verifies, and adjudicates; reviewing the code itself and calling it the local review is /signoff's one unforgivable move, and it is this skill's too). It is one fleet of `claude-session` calls, one per lens /signoff's Step 3 selects for this run (LEAN's `spec`, `correctness`, `seams`; DEEP's additions; the `REVIEW.md` passes marked `on`; the depth stated in one line before launch, as /signoff requires), each: `row: claude-session`, `profile: repo-with-tools`, `workspace` `<run dir>/worktree` (Step 3's worktree detached at the reviewed head — never the live checkout, so a lens that runs tests or mutates files does it in an isolated copy at the same commit the export holds, and readers' profile line, which names the request's `workspace`, points the reviewer at that copy), `documents` the build doc by path plus `REVIEW.md` when present, `mandate` `<run dir>/local-<lens>.md` — the lens's brief as /signoff's Step 3 defines it (quoted from /signoff's live SKILL.md at run time, never paraphrased), the vertical scope, the base commit and boundary from Step 3, /signoff's ledger-versus-spec line, and its reporting shape (claim · `file:line` · concrete failure scenario · severity · confidence, everything reported, plus what the lens tried to break and could not) — `floor: opus` (/signoff's Step 0 floor, passed, never assumed), `session_model` the exact model id this session's system prompt says it is powered by, `call_id` `<run id>-local-<lens>`, no `isolation` (the workspace is already the isolated copy; the Agent tool's own worktree would come up at `main` while readers' profile line still named the workspace), no `effort` and no `model` (an unpinned `repo-with-tools` call runs as a plain subagent inheriting the session model through the Agent tool, so the local fleet needs no Workflow tool and no `.readers/` copy lands in the reviewed repo), and no `authorized` (a Claude row never carries it). A local call refused `floor-refused` means this session is below /signoff's floor: STOP per /signoff's Step 0 and never emit the `VERTICAL:` block. A local lens whose status is `transport-failed`, `empty`, or `incomplete` is re-sent once as a fresh call id (`<run id>-local-<lens>-2`; a call id is single-use and this row needs no word); a second failure, or a deterministic refusal (`unknown-model`, `invalid-request`, `lane-unavailable`, `profile-unsupported`, `version-mismatch` — the same request refuses the same way, so it is never re-sent), leaves the local review incomplete, which is a STOP with the honest state and the status as the reason — the local review always completes or the run does not. The local review forms its findings **before reading any outside section** (independence): the local summon completes and its `raw_text` is merged and verified (Step 5) before the outside summon goes out, and it runs regardless of which outside reviewers were picked or how they fare.

**Outside, on Tony's word from Step 2.** Each outside reviewer Tony named is one call with `row` the row he named, `mandate` `<run dir>/mandate.md` (Step 3's composed mandate), `authorized: true` (his answer in this run is the word), `call_id` `<run id>-<row>`, `model` only when he typed an id against the row, and the profile the row supports — with **one deliberate inversion, stated here so nobody "fixes" it back: jpb starves its boxes of repo access (a neutral empty directory — parity for a product-box); /vertical feeds the repo to them — the export directory IS the workspace, because reading the code is the assignment.** On the rows that can read a workspace (`gpt-astra`, `gpt-sol`, `gemini`) that is `profile: repo` with `workspace` `<run dir>/export/`; on the rows whose model has no filesystem (`deepseek`, `qwen`, the OpenRouter rows, which refuse `repo` as `profile-unsupported`) it is `profile: packet-only` with `documents` the staged export files from Step 3 and `output_budget: 32768` (a review's worth of output; the row's default output cap would otherwise eat most of its window and a whole-repo packet comes back `oversize`). The sidecar's `profile` records which ran, and the verdict names it per reviewer. Web access stays OFF in both skills: the model id, effort, sandbox, working directory, web-tool ban, and guards are the roster row's and the profile's, resolved by readers; this skill types none of them, and a reviewer's no-web parity and isolation record are its sidecar's `parity` and `isolation` fields — never a sentence typed here.

Each `READERS:` line is one reviewer's result. `ok` means the review is that call's `raw_text` (readers' verbatim capture). Any other status on an outside call — `lane-unavailable`, `unauthorized`, `oversize`, `empty`, `incomplete`, `transport-failed`, `profile-unsupported`, any refusal — is that reviewer **dropped with the status and the sidecar's `reason` recorded**; never retried, never re-sent under another id in this run (a retry is Tony's word in a fresh run). Readers' own guards decide content: an empty reply is `empty` whatever the transport's flag said, and a complete reply under an error flag is `ok` with the anomaly in `reason`, which the Method line repeats. The run continues with the survivors. The local review always completes.

## Step 5 — Merge and verify

- **Dedupe** on `file:line` + claim. Convergence across independent reviewers is signal — note it on the merged finding, never list it twice.
- **Adversarially verify every outside finding** against the source before it reaches Tony: read the code at the claimed location, check the failure scenario holds, stamp CONFIRMED or PLAUSIBLE per /signoff's rules. A hallucinated `file:line` is a refutation unless Claude locates the real site and says so on the finding. Refuted findings are dropped from the verdict and counted: the verdict carries `Refuted: N`.
- **Re-gradings are recorded, never silent.** Any change the merge makes to a reviewer's stated severity or confidence — a demoted MAJOR, an upgraded PLAUSIBLE — is noted on the merged finding with one clause of why (e.g. "GPT graded MAJOR; demoted: no data-loss path"). The verdict's audit trail is the product; an unexplained re-grade poisons it.
- **Compare against the per-slice record.** Claude (never the outside reviewers) reads the on-disk record — the build doc's punch-list history, its recheck blocks, and `Status:` lines; per-slice chat verdicts are gone with their sessions and are never assumed. Call out in the verdict prose: repeats (a finding the ledger already caught — note its recorded disposition) and misses (a ledgered finding marked fixed that no one re-found — verify it stayed fixed). A cleanly signed-off slice may have no ledger entries at all; the comparison covers what the record holds and says so.
- **Locationless concerns never reach the verdict.** A reviewer's "concerns without location" stay in the raw appendix unless Claude verifies one into a real `file:line` (then it is an ordinary finding). This is /signoff's evidence rule applied at the merge.

## Step 6 — The verdict doc

One file per build: `docs/reviews/<YYYY-MM-DD>-vertical-<feature>.md` in the reviewed repo (`<feature>` is the doc's identity: the `<topic>` of a `docs/plans/<YYYY-MM-DD>-<topic>.md` name, else the filename minus `-build-plan.md`; the date is the first run's). Before writing, glob `docs/reviews/*-vertical-<feature>.md`: a hit is the build's file and this run appends to it; no hit means this is the first run and the file is created with today's date. A rerun for the same build appends a dated block to that same file — never a second file, never overwriting an earlier block; the file is never cleaned up (git history is the only archive). Create `docs/reviews/` on first use. This is the skill's ONLY write: never code, never the build plan, never a `Status:` card.

Structure, top to bottom:

1. **THE VERDICT** — the merged verified findings only. /signoff's severity → verdict mapping names the outcome (its `## Severity bar` when `REVIEW.md` is present); findings appear in /signoff's punch-list line format (severity · `file:line` · claim · scenario · which reviewer(s) found it); `Refuted: N`; the repeats/misses prose from Step 5; the `REVIEW.md` lines — each pass it skipped with its reason, and each repo-specific check by name, held or found — or one line saying the file was absent and defaults applied. (The verdict doc is its own record — /recheck's checklist reads the build doc's ledger, not this file; routing fixes from a vertical verdict is Tony's instruction after reading it.)
2. **Method line** — what ran and what didn't: the base commit and how Step 3 determined it; the run id; reviewers used and dropped, each dropped one with the `READERS:` status and the sidecar's `reason`; per outside reviewer the row, the effective model id the `READERS:` line carries, the profile the sidecar recorded (`repo` or `packet-only (no workspace)`), its parity line and isolation label copied from the sidecar's `parity` and `isolation` fields (never typed here), any anomaly readers recorded in `reason`, and for a packet-only row the files left out of the packet; per local lens the row, effective model id, and profile; how the local review verified (per /signoff's declare-the-method rule); and any collapsed gate.
3. **Unverified appendix** — one section per reviewer, local lenses and outside reviewers alike, each call's `raw_text` VERBATIM (readers' capture; a packet-only reviewer's citations carry the staged names from Step 3, left as written), under this banner: *"Raw reviewer output — unverified. Findings here that are absent from the verdict above were refuted or could not be verified. Nothing in this appendix has standing."*

The verdict is section 1 alone. That is how "nothing unverified lands in the verdict" and "every model's raw section verbatim" coexist.

## Step 7 — Stop

Report the verdict in chat and stop. Offer fixes; never start them. Fixing is Tony's separate instruction after reading the verdict — same as /signoff, and no invocation wording collapses this gate for the fixes themselves. The git gates are untouched: no push, no PR, no merge.

## The rules

1. **The gate is real.** Every slice `signed off`, or report-and-stop. Only Tony's invocation wording overrides, and the override is recorded.
2. **The ask is real.** Every run, wait for the answer. No remembered answers, no silence-defaults. Outside sends happen only on this run's answer.
3. **Secrets are physically absent.** Outside reviewers read the tracked-files-only export, never the working tree. No exceptions, no "it's probably fine."
4. **Cold means cold.** No prior verdicts, no chat context, no cross-reviewer leakage in any packet.
5. **Nothing unverified lands in the verdict.** Every outside finding is verified or it stays in the appendix. `Refuted: N` is always reported.
6. **Survivors continue.** A dropped reviewer is recorded with its `READERS:` status and reason, never papered over; the local review always runs.
7. **One write.** The verdict doc, dated, never overwriting. The build plan, its cards, and `REVIEW.md` belong to the other stations.
8. **Stops at the verdict.** No fixes, ever, from this skill.
9. **/signoff is the law of review mechanics.** Where this file is silent, its SKILL.md governs; nothing here restates it to drift.
10. **Interactive only.** /vertical runs with Tony present to answer the gate, the ask, and the base — never headless, never from a script or cron.

When executing this skill required working around, reinterpreting, or excepting one of its rules, the report carries one line marked `SKILL NOTE:` — what and why, addressed to the skill's author, not the project; a clean run carries none.

## What NOT to do

- Don't run with any slice short of `signed off` unless Tony's own invocation said to — and record it when he does.
- Don't send anything outside without this run's answer to the ask — no defaults, no memory.
- Don't point an outside tool at the live working tree — export tracked files or don't send.
- Don't put prior verdicts, chat context, or one reviewer's output in another's packet.
- Don't let an unverified outside finding into the verdict section — appendix only.
- Don't type a model id, effort, sandbox, or working directory into a request — readers' roster carries them; a roster row moves only by PR on Tony's word, and a typed id is Tony's, passed as `model` on the row he named.
- Don't treat a `READERS:` status other than `ok` as a survivor — it is a dropped reviewer with its reason, and readers already decided what an empty reply means.
- Don't put `authorized: true` on a call Tony's answer did not name, and never on the local row.
- Don't re-send a call under a used call id or reuse a run id across runs — a retry of an outside reviewer is a fresh run on Tony's word; the one local re-send takes a fresh call id.
- Don't point a local lens at the live checkout — the worktree Step 3 cuts at the reviewed head is the workspace, and it is removed after the run.
- Don't fix anything, don't touch the build plan or its cards, don't write `REVIEW.md`, don't write a second file.
- Don't push, open a PR, or merge — the git gates are Tony's, always.
