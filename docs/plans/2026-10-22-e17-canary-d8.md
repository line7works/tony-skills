# E17 canary: every caught CLI secret gets its lasting withhold record (build plan, 2026-10-22)

Intent: sun-v2's sunset withholds the two Vercel CLI secrets its T04 rows name (`cli_secrets`). When a caught secret already stands in the run's own records, the tool writes a value-free disproof record and stops, so that every later invocation withholds it too. Today only the first such secret gets that record. With both secrets already in the records, the next status form prints the second. This plan fixes that, and nothing else.

Source: the outside reviewer's J7 check (E16 contract A157), finding D8, its closing rule: "Persist value-free disproof for every newly caught secret before stopping, and prove that subsequent status forms withhold both while earlier records remain byte-identical." The owner picked this task as the E17 canary (D7), typed "Go on 1".

Constraints:

- The repo is public: no secrets, personal paths, mail addresses, key-shaped strings or em dashes in any file. One exception: the slice heading's separator, which the build-doc form requires (the owner: "em dash ok").
- Never rewrite stored history: earlier records stay byte-identical.
- Tests run as `cd plugins/sun-v2/lifecycle/scripts && PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 -m unittest discover -s tests -p '<module>.py'`. Never run against the owner's real machine, accounts or providers.
- No push, no PR, no merge: the owner's word only.

## Slice A — one disproof record for every caught secret

Status: signed off

Requirements:

- In `held_cli_secrets` (`plugins/sun-v2/lifecycle/scripts/sun_core/effects.py`), every named CLI secret whose value already stands in the run's own records, and is not already withheld by an earlier record, gets its own value-free disproof record (`channel: cli-added secret`), written before the run stops. Today the loop keeps only the first secret's spans (`owed is None`).
- Each record names where its value rests and holds no value, as the first one does now.
- The run still stops once, "a safe ground disproved", after all the records are written.
- Every later invocation reads both records back and withholds both values: the next status form, and every later form, holds neither secret.
- Earlier records (the look's inputs, manifests and preview) stay byte-identical. Nothing else in the tool changes behavior: a single caught secret, or none, works exactly as today.

Checks:

- A new test, red before the change: two named secrets, both already in the run's records. The go stops with two disproof records, neither holding a value; the next status form and the resume's forms hold neither secret; every file the look wrote is byte-identical.
- `test_j7_review.py` and `test_j6g_cli_keys.py` still pass in both runtimes (the pinned `-I` run with an empty environment, and the site run).
- The full sun-v2 suite in both runtimes, the sweeps last, passes.

Footprint: plugins/sun-v2/lifecycle/scripts/sun_core/effects.py, plugins/sun-v2/lifecycle/scripts/sun_core/screen.py, plugins/sun-v2/lifecycle/scripts/tests/test_e17_canary_d8.py

Not in this slice: L-24 (the link step's stray edits) and every other punch-list item; any row, schema or provider file; `disproof.py`; the skills' text; the version number.
