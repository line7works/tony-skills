# sunrise-live-run-fixes — build plan (2026-09-05)

Intent: Two defects in `/sunrise` surfaced by its first live run after the agent-file flip (project Banana Dunk, slug `banana-dunk`, archetype static, 2026-09-05, sun plugin cache `75b836b0c1ff`). First, `npx vercel link --yes` derives the Vercel project name from the directory `<Name>`, and Vercel rejects mixed case (`Banana-Dunk`, HTTP 400); the run had to be redone with `--project banana-dunk`. Second, `vercel link` appends `.vercel` and `.env*` to the end of `.gitignore`, below the `!.env.example` negation Phase 1 step 3 added, so `.env.example` is ignored again; it stayed tracked in the test only because it was already committed and was fixed by hand. This build makes the skill pass the slug explicitly and re-assert the negation after linking, so the next sunrise does not need a hand fix at either point. For Tony, who runs `/sunrise` once per new project and expects a green baseline without intervention. Source of every requirement: the two 2026-09-05 Inbox notes in `docs/feedback.md` (findings A and B, tagged `sunrise live run (Banana Dunk) · sunrise`) and the current text of `plugins/sun/skills/sunrise/SKILL.md`.

Constraints:
- Stack: the skill is a Markdown file, `plugins/sun/skills/sunrise/SKILL.md` (541 lines on `main` at 2baaecb). No code, no test runner in this repo. Verification is mechanical (`grep`, `awk`, `git diff --name-only`) plus one fresh-session read.
- Fresh-session reads do NOT use `claude --plugin-dir plugins/sun`: that flag loads the branch copy beside the installed copy rather than instead of it, so both `/sunrise` skills are present and the answer is ambiguous (recorded in `docs/evidence/agent-file-flip/slice-a-requirement-map.md` and the `## Deviations` of `docs/plans/2026-09-04-agent-file-flip.md`). Inside this slice the fresh session is plain `claude -p` from the repo root, told to read the skill file at its checkout path. The read from the installed cache happens only after merge and Tony's reinstall (see Out of scope).
- Source of truth: this repo is canonical, but a running machine executes the marketplace cache under `~/.claude/plugins/cache/tony-skills/sun/`. A change here reaches a session only after it lands on `main` AND Tony runs `/plugin update sun@tony-skills`. Nothing in this slice may assume the running skill has changed.
- The Phase 8 kit check stays exactly the four lines it is today; they mirror the vault kit note's "Verifying a repo against the kit" verbatim, and a fifth line there would drift the skill from the note. The `.env.example` check therefore lives in Phase 3, at the point where `vercel link` does the damage.
- Vocabulary is the skill's own (Phase 0 step 3): `<Name>` is the repo and local dir (Tony's casing kept), `<slug>` is kebab-case lowercase. Vercel project names must be lowercase, so the Vercel project is `<slug>`; `<Name>` stays the repo and directory name everywhere else.
- Git gate (repo `CLAUDE.md` and Tony's global rules): feature branch, local commits fine, stop before `git push` and `gh pr create`; Tony says "PR" then "merge" in the terminal. `docs/feedback.md` is already dirty on `main` (an uncommitted `/fb` note from the orchestrator plus the two notes this plan builds from); it rides along in this slice's commit.
- Repo invariants that bind here (repo `CLAUDE.md`): the repo is public, so nothing Tony-specific goes in by default; asset references stay `${CLAUDE_PLUGIN_ROOT}/...`; the `sun` plugin keeps both skills together.
- Evidence for the fresh-session read is recorded verbatim at `docs/evidence/sunrise-live-run-fixes/fresh-session-read.md` (pattern from `docs/evidence/agent-file-flip/fresh-session-rerun.md`: the question, the whole answer, the checkout commit it read).

## Slice A — sunrise live-run fixes
Goal: `/sunrise` links Vercel under the lowercase `<slug>` explicitly and leaves `.env.example` tracked after `vercel link`, with no hand fix at either point.
Requirements:
- R1: Phase 3 step 1 passes the project name explicitly: the command becomes `npx vercel link --yes --project <slug>`, and the parenthetical stops claiming the project is named `<Name>`; it says the Vercel project is `<slug>` and why (Vercel requires lowercase; the directory-derived `<Name>` was rejected with HTTP 400 on 2026-09-05). (finding A)
- R2: Every other place the skill names the Vercel project uses `<slug>`: today that is the Phase 0 preview block's line `Vercel   link project <Name> (auto-connects GitHub repo; auto-deploys on)`. (finding A: "the prose stops claiming the project is named `<Name>`")
- R3: Phase 3 gains a step, immediately after `vercel link` and before the `git connect` confirm, that re-asserts `!.env.example` as the LAST line of `.gitignore` (because `vercel link` appends `.vercel` and `.env*` to the end, below the Phase 1 negation) and re-runs Phase 1 step 3's verification: `.env.example` not ignored, `.env.local` still ignored; `.vercel` stays ignored. The step says in one sentence why it exists, so a future reader does not delete it as redundant with Phase 1. (finding B)
- R4: Phase 1 step 3's `.gitignore` bullet points forward to the Phase 3 re-assert in one clause, so the two negation sites read as one rule and not a copy-paste. (finding B; keeps the skill's rule lists consistent with its body)
- R5: `docs/feedback.md` gains one line under the real `## Dispositions` heading (the heading line itself, not the backticked mention in the intro paragraph) dated 2026-09-05, naming the two 2026-09-05 sunrise Inbox notes and pointing at Slice A of `docs/plans/2026-09-05-sunrise-live-run-fixes.md`. Additive only; no Inbox line is edited, reordered, or removed. (the file's own Flow line: dispositions are additive-only; precedent, the two 2026-08-02 lines)
- R6: Nothing else changes: not `sunset/SKILL.md`, not any other plugin, not the Phase 8 kit check's four lines, not Phase 3's Electron env-plane step.
