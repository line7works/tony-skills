## Slice A - guide findings counts each GUIDE note once

Status: signed off

Requirements:

- `tools/guide-findings.py` reads the `docs/feedback.md` of every checkout under `~/Developer`, and a worktree carries its own copy of that file. A `GUIDE:` line whose text is the same in more than one of those files is one finding: it is counted once in the report's table and listed once, citing one of the files it came from. The same holds for `--json` and `--check`, and a malformed `GUIDE:` line repeated across checkouts is reported once.
- Two `GUIDE:` lines whose text differs are two findings, wherever they sit, including two different lines in the same file.
- Added on the owner's ruling after the first signoff run ("yes to 1", 2026-10-28): a `GUIDE:` line repeated inside one file, the same text twice, is also one finding. The same text means the whole line, date, thread and area included.
- Findings from the capture log (`docs/guide-findings.md`) are read and counted as before.
- A new test, `tools/tests/test_guide_findings.py`, runs the tool against a throwaway home folder: the same line in two checkouts counts once (fails on today's tool), two different lines count twice, and a log finding still counts. The test uses only the standard library.
- No other change.

Checks:

- guide findings counts each GUIDE note once: /usr/bin/python3 -m unittest discover -s tools/tests -t tools/tests -p test_guide_findings.py

Footprint: tools/guide-findings.py, tools/tests/test_guide_findings.py
