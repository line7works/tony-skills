## 1. What E14 delivers

Plan text, verbatim. **Artifact:** four portable station cores, their necessary templates, and
host-specific interaction/visual integrations. **Done when:** recorded owner decisions pass into
architecture and slices without invention or re-interview; document selection handles ambiguity;
inspect receives the permitted primary evidence; no implicit import of v1 signoff remains. Local
visual generation and external publication have distinct actions. **Runs:** C authors; S checks
records; qualified v2 signoff uses a fresh R reviewer. **Dependencies:** E12 to E13. **Owner
gate:** D5 only if changing invocation behavior. "This step rebuilds those stations. It does not
invoke v1 precon or architect to restart decisions already settled in this packet."

D5 as ruled (the plan's decision table and the board's rulings row): keep the existing accepted
summons, add equivalent native controls where the harness has them, test manual-only per harness.

In plain words: five things get built.

1. **The frame (slice 1).** The station-loop contract the four cores follow; the shapes they read
   and write; the shared helpers (reaching the records component, finding a document, reading a
   scope doc's ledger, rendering and parsing the templates); the adapters and setups for Claude
   Code and Codex; the seeded cases with their answer key behind the wall; the test that fails
   when any core leans on a v1 skill. Two carried items ride at the front of it (pick P7).
2. **A portable precon core.** The idea stage's harvest, triage, rounds, ledger, exit test and
   gate, with the ledger's traceability and the scope doc's placement done by script.
3. **A portable architect core.** The drawings step: the input gate, the exit ramp, the
   interview, the one living architecture doc, the visual, the blind review, with the record of
   precon's decisions passed in by script and never re-asked.
4. **A portable blueprint core.** The sliced build doc, with every requirement carrying its trace
   and the load-bearing forms rendered by script, so /build, /signoff and /recheck keep reading
   what they read today.
5. **A portable inspect core.** The plan check, with its packet built by script from the
   permitted documents alone, its review mechanics stated in its own contract, and its findings
   kept in the records component.

Out of scope: vertical, handoff and ship (E15); sunrise and sunset (E16); cutover or retirement of
any v1 skill (P6; E17 to E19); any change to `plugins/records/` (E13-2 stays, ruling E14-2); any
change to what `recheck-v2`, `build-v2` or `signoff-v2` decides (ruling E14-8); the OpenCode
adapters (E13 pick P3 stands); live model trials as a suite; a third harness.

## 3. Boundaries every lane keeps

- One writer per worktree. A builder writes only under the folders its slice names (section 15)
  and the scratch directory it is given. Never `plugins/records/`, never `plugins/recheck-v2/`,
  never `plugins/build-v2/` or `plugins/signoff-v2/` (slice 1's C4-1 item excepted, in the file
  it names), never `plugins/readers/` (slice 1's readers item excepted, in the files it names),
  never any v1 plugin folder, never another lane's folder, never `.claude-plugin/marketplace.json`
  (the control room adds entries at close), never `docs/feedback.md` or `docs/ideas.md`.
- A builder never runs `git add`, `commit`, `stash`, `checkout`, `reset`, `merge`, `worktree`,
  `branch`, or any git command that changes a worktree, its index, or its branches. `status`,
  `log`, `diff`, `rev-parse`, `show`, `archive` to a temporary directory are fine. The control
  room checks every round and makes every commit and every local merge.
- Runtime floor: `/usr/bin/python3` 3.9.6 and git 2.50.1. Python 3.9 syntax. Standard library
  only, with the one declared exception: `jsonschema` at the pin in force in the E13 cores' PEP
  723 blocks (`jsonschema==4.25.1`), through `uv run`. A script started without it exits 3 with
  the pilot's message shape. `--help` and argument checks work without it.
- No network. No MCP tool. No model call inside any script. A core's script never launches a
  harness and never publishes anything; a skill body may direct the executor to summon a reader
  (through `readers`) or to publish a visual (through the harness's own tool, ruling E14-6), and
  a test never does either.
- A station reaches the records component through the resolver snippet and the CLI only (E12
  ruling O2). It never opens a log file, never imports `records_core`, never copies the
  component's code beyond the snippet. It confirms `interface_version` 2 through
  `component-identity` and stops with exit 3 and a plain message when the component is missing or
  speaks another version. A core that writes no event (ruling E14-9) does not open the component
  at all and says so in its contract.
- A core never reads a v1 skill's files at run time, never shells to one, and never defers to one
  as law (ruling E14-7). Its code book, where it needs one, is a v2 sibling resolved the way the
  records component is resolved (route 3a, then 3b), never a personal path.
- Tests build their fixtures into a temporary directory and clean up. Nothing is written into a
  worktree by a test run (`PYTHONDONTWRITEBYTECODE=1`; no `__pycache__` left).
- Install probes run only in isolated homes, never the live `~/.claude` or `~/.codex`.
- The repository is public. Fixtures are synthetic: no text copied from another repository, no
  personal, legal or financial content, no personal paths, no machine names, no key-shaped strings.
- Test first for every behavior a seeded case or a required test names: the failing output is
  recorded before the code that makes it pass.
- No em dashes in anything written for this step.

## 6. Rulings of this contract

- **E14-1, behavior is kept, the mechanics move.** No core changes what its v1 station decides:
  precon's harvest-before-ask, triage, frontier rounds, ledger tags, property line, exit test and
  gate; architect's input gate, exit ramp, candidates, razor, one-way doors, living doc, visual
  and blind review; blueprint's harvest, interview, slicing rules, load-bearing forms and
  read-back; inspect's lenses, the ask, the lane-down rule, the no-record rule, verify and
  adjudicate, the two writes and the stamp. What moves is where the deterministic half lives (a
  script, not prose) and where inspect's findings are kept (P8). A proposed change to any
  decision is the owner's ruling and lands in section 18.
- **E14-2, the records component is frozen in this step.** At close, `git diff --stat <branch
  point> -- plugins/records` prints nothing. A station that needs something the interface does not
  offer reports it as a question and stops on that point.
- **E14-3, one pattern, and the frame's files are canonical.** Each core follows the E13 shape:
  `SKILL.md` as the portable procedure; `references/` with a contract, schemas, examples and the
  templates; `scripts/` with one CLI phase driver, a `<station>_core/` library and `tests/`;
  `adapters/<harness>/`; `setups/<harness>/`; `evals/seeded-cases/`. What slice 1 writes as shared
  (section 8) is copied into each core byte for byte and held equal by a test in each core; a lane
  that needs a shared file to change asks the control room, which changes it in slice 1's worktree
  and merges it into every lane. Nothing shared is reinvented in a lane.
- **E14-4, the executor decides, the script records.** A script validates inputs, finds
  documents, reads the ledger, builds packets, talks to the records component, renders and parses
  the templates, validates results and writes the documents. It never judges an idea, an
  architecture, a plan or a finding. The judging is the executor's (precon, architect, blueprint)
  or the independent reader's (inspect, and the cold reads the other three offer), and what they
  conclude is recorded with who concluded it.
- **E14-5, versions.** Each new plugin starts at `0.1.0` with its own `interface_version` 1 in
  every CLI response. `build-v2` and `readers` bump their patch version for their slice 1 items.
- **E14-6, the visual has two actions.** `architect-v2` renders the visual locally (`render-visual`
  writes `<slug>-architecture.html` beside the doc and nothing else) and publishes it as a separate,
  named executor step through the harness's own artifact tool, recorded in the doc's `Artifact:`
  line by `record-publish`. The script never publishes; a run that renders and does not publish
  ends in a named result that says so. The default stays v1's (publish, private, same URL across
  runs); `publish: false` in the input skips the step and the result names it.
- **E14-7, no implicit import of v1.** A test in every core (`tests/test_no_v1_import.py`) reads
  the core's `SKILL.md`, `references/`, `adapters/` and `scripts/` and fails on any reference to a
  v1 plugin path (`plugins/precon/`, `plugins/architect/`, `plugins/blueprint/`, `plugins/inspect/`,
  `plugins/build/`, `plugins/signoff/`, `plugins/recheck/`), any "is the law where this file is
  silent" deference, and any subprocess whose argv names a v1 skill. Where a v1 station stated its
  mechanics by deference (inspect's "signoff's SKILL.md is the law"), the v2 core states them in
  its own contract, copied from `signoff-v2`'s contract where they are rules, in its own words
  otherwise. `inspect-v2`'s code book is `blueprint-v2`'s installed `SKILL.md`, resolved as a
  sibling (route 3a, then 3b), never the v1 file and never a personal path.
- **E14-8, the v2 back half is frozen.** `recheck-v2`, `build-v2` and `signoff-v2` do not change
  in this step beyond C4-1 (P7); `readers` does not change beyond the A12 route (P7). At close the
  diff of each against the branch point holds those two items and nothing more. A change to what
  recheck decides is a stop (E13 A11 stands).
- **E14-9, records for the front.** `precon-v2`, `architect-v2` and `blueprint-v2` write no event
  and do not open the component (the records assessment's question 2: no; a scope doc, an
  architecture doc and a fresh build doc carry no finding and no card move). The log of a build doc
  is opened by the first station that raises or moves a card, as today. `inspect-v2` raises per P8
  and clears nothing.
- **E14-10, document selection is one helper.** The hunt for a scope doc, an architecture doc or a
  build doc is one shared function with one result shape: the candidates it found, where it looked,
  and one of three outcomes: `none` (report; the calling core's own rule says what follows), `one`
  (taken, named), `several` (listed for the executor to put to the owner, never picked). The
  homes and globs are the v1 skills' own (repo `docs/scope/`, `docs/architecture/`, `docs/plans/`,
  the older flat names, `~/Documents` staging), read from the core's contract, never guessed.
- **E14-11, the record passes forward.** A decided ledger line of a scope doc reaches the
  architecture doc and the build doc by script (the ledger reader emits every line with its tag,
  source and a stable line id) and is never re-asked: the recorded answer of `architect-v2` and
  `blueprint-v2` lists the questions the executor put to the owner with the ledger lines each one
  touches, and `record-answer` refuses (exit 5) a question that touches a `decided` line. A line
  the executor asserts that traces to no ledger line, no repo path and no answered question of this
  run is refused the same way. `parked` and `open` lines pass forward as `parked` and `open`.
- **E14-12, the load-bearing forms do not move.** The scope doc, the architecture doc, the build
  doc and the punch-list and stamp lines keep v1's section names, labels and `·`-separated fields
  byte for byte, so `build-v2`, `signoff-v2`, `recheck-v2` and the records importer read what they
  read today. The templates are parsed and rendered by one shared module whose round trip is
  tested; a form change is a stop.

- The station loop of 7.2 and the helpers of 7.3, byte-identical, held equal by test (E14-3).
- The same input discipline as the E13 cores: one validated input per run, a schema, accepted and
  rejected examples, caller values bound as data, never pasted into shell text; the workspace an

  absolute and outside the workspace.

  loop skill; a collapsed gate in the owner's invocation is the executor's to act on, and the core

## 9. The precon core (`plugins/precon-v2/`, lane P of slice 2)

  after triage and only at the first settled line.
- **The property line.** The script has no network and no reader of anything outside the
  workspace, the staging home and the run directory; a question the answer marks `needs research`
  is a `parked` line, never resolved in the run.
- **The exit test.** The `readers` request per section 8, `profile: starved`, the cold-reader
  mandate verbatim, one call per named reader under the sitting's run id; the cold-read doc written
  verbatim from each `raw_text` before any triage, with the disposition lines added by a later
  `record-answer`; a non-`ok` status reported by status and reason with no section.
- **The gate.** The result's last field is the one-line justification that every branch was
  visited or parked; a run without it is not `complete`.
- Records: none (E14-9). Required tests: the seeded families of section 14 that belong to precon,
