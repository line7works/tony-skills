# agent-file-flip — build plan (2026-09-04)

Intent: Phase 2 of the agent-file flip program, the tony-skills part. Three changes to the loop skills in this repo: (a) `/sunrise` seeds new repos with `AGENTS.md` as the instruction body and `CLAUDE.md` as a one-line `@AGENTS.md` stub, per the vault's repo doc kit, and adopts any scope or architecture docs that were written before the repo existed; (b) every loop skill writes its paperwork into fixed subfolders of the repo's `docs/` instead of `~/Documents`; (c) `/signoff`, `/recheck`, and `/vertical` read a per-repo `REVIEW.md`, which `/signoff` creates on its first run in a repo. For Tony, so every new repo carries one instruction body that Claude Code, Codex, Cursor, and Copilot all read, and so the idea-to-verdict paper trail is version-controlled in the repo that owns it. Source of every requirement: `docs/scope/2026-09-04-agent-file-flip.md` (the precon scope doc, 2026-09-04; written at the flat path `docs/agent-file-flip-scope.md` and moved here by Slice A), the vault notes it names, and the two blueprint questions answered 2026-09-04.

Constraints:
- Stack: the skills are Markdown `SKILL.md` files under `plugins/<name>/skills/<name>/`. No code, no test runner in this repo. Verification is mechanical (`grep`, `ls`, `git ls-files`) plus a fresh-session read of a changed skill, started from the checkout with `claude --plugin-dir plugins/<name>` so the check runs the edited file rather than the installed cache.
- Source of truth: a change here reaches a running machine only after it lands on `main` AND the plugin is reinstalled (`/plugin update <name>@tony-skills`). Reinstall is Tony's manual step after each slice's merge, Studio only (scope doc). Nothing in a slice may assume the running skills have changed.
- The running stations are the cached copies until reinstall. After Slice A moves this build doc into `docs/plans/`, the cached `/signoff`, `/recheck`, and `/ship` cannot find it by their old hunt. Until the plugins are reinstalled, every station invocation for this program names the doc by path: `docs/plans/2026-09-04-agent-file-flip.md`. All of those skills accept a named doc.
- Layout and naming standard: `~/ObsidianVault/01-domain/repo-doc-kit.md` (live note). Folders: `docs/scope/` (precon), `docs/architecture/` (architect), `docs/plans/` (blueprint), `docs/reviews/` (signoff, recheck, vertical, inspect, plus precon cold reads and architect blind reviews). Names inside: `YYYY-MM-DD-<topic>.md`. A superseding doc names the file it supersedes in a prose line at the top; hunts never parse it. Body-content standard for instruction files: `~/ObsidianVault/01-domain/agents-md-best-practices.md` (the spec sheet); the Claude-only layer: `01-domain/claude-code-companion.md`. When sources disagree: this build doc over the scope doc over the handoff; the live kit note over all of them for layout and naming; the spec sheet for body content.
- Pre-repo staging is the one exception to "never `~/Documents`": when no repo owns an idea, `/precon` and `/architect` keep writing where they do today (`~/Documents/<idea>-scope.md`, `~/Documents/<slug>-architecture.md`, `~/Documents/precon-cold-reads/`, `~/Documents/architect-reviews/`). `/sunrise` empties that staging when it creates the repo (Slice B).
- Git gate: one PR per slice, Tony says "PR" and "merge" each time; local commits fine; never push to `main`. Feature branches per the repo's CLAUDE.md.
- Repo invariants that bind here (repo `CLAUDE.md`): the repo is public, nothing Tony-specific goes in by default; asset references stay `${CLAUDE_PLUGIN_ROOT}/...`; `sun` keeps both skills; `signoff` stays report-only (writing `REVIEW.md` and a verdict doc is recording, not fixing) and keeps its independence, anti-rubber-stamp, and Opus-floor rules; `wargame`'s floor and anti-theater rule are untouched (not in this build).
- Every skill's "What NOT to do" and rule lists stay consistent with the edited body: a path rule changed in one place is changed everywhere the file states it.
- Each slice records a requirement map at `docs/evidence/agent-file-flip/slice-<x>-requirement-map.md` listing every requirement with the file and line(s) that implement it (pattern from `docs/evidence/architect/`).

Out of scope:
- The fifteen existing flat docs in this repo's `docs/` (three `*-scope.md`, twelve `*-build-plan.md`) stay where they are — reason: Tony (blueprint Q1, 2026-09-04); the second hunt tier exists so finished work needs no migration. Only this program's own two docs move.
- Per-repo flips, the Pour-Guys body draft, `DESIGN.md` backfills, the per-repo migration checklist, program close-out beyond this repo — reason: phases 3 to 6 of the program, run from `~/Documents/handoffs/2026-09-03-agent-file-flip-handoff.md`, not from this build (scope doc).
- Any edit to `/sunset` — reason: verified 2026-09-03 that it never reads or writes a repo's instruction files, and loop artifacts under `docs/` travel with the repo into `_archive`; Slice D re-reads and records that, nothing more (scope doc).
- `/architect` for this build — reason: a template swap has no drawings (scope doc).
- Flipping tony-skills' own `CLAUDE.md`/`AGENTS.md` — reason: that is this repo's turn in phase 5, one PR per repo.
- Dropping precon's `~/Documents` fallback — reason: rejected by Tony (precon Round 4); pre-repo ideas need a home before sunrise, and the order precon → architect → sunrise → blueprint is set by the architect skill.
- Cleaning up or rotating review docs — reason: Tony ruled "never clean up" (precon Round 3); git history is the only archive.
- Any change to `/fb`, `/digest`, `/wargame`, `/jpb`, `/huh`, `/shutdown` — reason: not loop paperwork writers (scope doc).
- A live `/sunrise` or live `/signoff` run as an acceptance test inside a slice — reason: a live sunrise creates a GitHub repo and Vercel project (outward, Tony's word), and a live signoff spends subagents; both are offered as post-merge checks in Slice D, run on Tony's word.

## Slice A — Relocate the loop's outputs and hunts
Goal: Every loop skill writes repo-owned paperwork into the kit's four `docs/` subfolders and hunts them there first, with flat `docs/` as the second tier so existing repos keep working.
Requirements:

The write is the kit template verbatim with the toggles applied and `<!-- verified: YYYY-MM-DD -->` stamped with today. Tony's word is a gate: no word, no file, and the run continues on defaults. (blueprint Q2, 2026-09-04)
