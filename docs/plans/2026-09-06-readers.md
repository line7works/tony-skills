# readers — build plan (2026-09-06)

Intent: Build `readers`, one component skill that owns the shared "cold outside read" the loop skills perform today, and convert every skill that brings in a reader to summon it. A reader is a model call whose whole job is to read supplied material and report on it: a fresh Claude subagent, GPT, Gemini, DeepSeek, or Qwen, run read-only against a caller-supplied mandate plus the input documents, with the output captured verbatim. Today that machinery is copied into five skills (inspect, vertical, precon, architect, jpb) with drift between the copies, and three more (signoff, wargame, recheck) spawn fresh Claude reviewers with their own text. For Tony, so that a new model is one roster row in one place, so his last pick per lane is remembered and suggested next time, and so the portable half runs from any harness with a shell (Codex today). Upstream record: `docs/scope/2026-09-05-readers.md` (32 decided lines, settled ground; this plan does not re-decide them) and the four cold reads in `docs/reviews/2026-09-05-precon-cold-read-readers.md`. Tony's words: "strip it out of all five and make one skill that has all of this ability in it, and then those five skills would just summon that skill inside of it. At any time when a new model comes out, we would just update that one component skill that all five are pointing at." Revised 2026-09-06 twice, after two /inspect runs each time (four stamps under Out of scope; the four punch-list blocks under `## Punch list` are the record of what changed and why). Statuses, each a backticked term on its own bulleted line in the contract: `ok` · `empty` (no content or whitespace only) · `incomplete` (truncated: finish reason, output cap, or interrupted stream) · `oversize` (rejected before any send, with the measurements) · `invalid-request` (malformed JSON, a missing required field, an unknown row id, an effort the row does not list, an output budget above the row's max or not an integer) · `lane-unavailable` (transport or credential absent, the Workflow tool absent for a call that needs it, or a `host` row requested through the shell entry, which cannot run one; reason text names which) · `unauthorized` (outside row without the flag) · `floor-refused` (a row or pick whose eligibility is `not eligible`, or a `claude-session` call whose `session_model` is absent or not on the roster's `eligible_session_models` list, when a floor is passed) · `unknown-model` (floor-bound call, id `not classified`) · `profile-unsupported` (the row does not support the requested profile) · `version-mismatch` (request `protocol_version` differs from the runner's) · `transport-failed` (with the transport's own error) · `capture-failed` (the model answered but `raw.md` could not be written) · `cancelled` (the caller interrupted the runner; the child is killed) · `timed-out` (the row's `timeout_s` elapsed; the child is killed; beats `incomplete`). Pre-send checks run in this order on every call, host or portable, and any failure returns before a child is launched or a request sent: request validity, version, authorization, profile support, floor and classification, lane availability, budget. The shell entry exits 0 only on `ok` and prints the result as JSON on stdout in every case, including `invalid-request`. `readers --version` prints the protocol version, which starts at `1`; `readers validate <request>` (a file path, or `-` for stdin) runs only the pre-send checks and prints `valid` or the refusing status, never dispatching; validate reads the named documents to size them, so a request with a missing document is `invalid-request`.
