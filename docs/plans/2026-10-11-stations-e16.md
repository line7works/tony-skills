## 1. What E16 delivers

Plan text, verbatim. **E16. Rebuild sunrise and sunset around explicit operations.** **Artifact:**
Shared lifecycle code, provider integrations, preview manifests, templates, and restoration
instructions. **Done when:** Disposable-project checks demonstrate correct vault/machine
preflight, staged-document adoption, credential-safe execution, declared Git behavior, resumable
partial failure, and restoration. Sunset's default preserves records without depending on a Trash
expiration window. **Runs:** X + S; C handles Claude-owned integration checks; O handles actions
requiring account/UI authority; R reviews. **Dependencies:** E12, E15. **Owner gate:** D6 for any
broader bootstrap Git exception. Real service operations require the authorization named in their
preview.

The plan, beside it: "The sound `.env.example` checks and database backup requirements remain. The
script extraction must test tracing and error output, not merely move the commands."

Plan amendment A8: "The lifecycle scripts follow the A7a helper interface, and the script
extraction tests the tracing and error-output paths for credential exposure. D6 as ruled: sunrise
may push the initial scaffold to `main` of a brand-new repo." Decision register 13 (D6), the owner:
"Sunrise push to main is fine because it'll be spinning up a brand new repo and everything, and
pushing to main won't hurt anything."

**Runs, read under the owner's crew ruling of 2026-10-11 (section 5, R2).** His ruling replaces
the plan's "X + S" line for this step: one Opus 5.5 builder at high per slice; the outside reviewer
(Astra, GPT-6, through `codex exec` on a sealed copy) at low is the checker of every hand-back; a
script with no model runs the suites. "C handles Claude-owned integration checks" is read as the
Claude adapter's own checks (section 6, E16-14). "O handles actions requiring account/UI authority"
is read as the owner: an operation only his account or his click can perform is his, shown to him
with the exact step and never attempted by the tool (E16-4; when it counts as done is the frame's
OP-9).

In plain words: sunrise starts a project on every layer it needs and sunset retires one on every
layer it lives on. v1 does both as prose a model follows, 541 and 316 lines. E16 rebuilds them so
that every change to the machine or to an outside service is an **operation**, as the frame
defines one (`2026-10-12-stations-e16-frame.md`, OP-1, OP-2, ROW-1). Five things get built.

1. **The lifecycle frame (slice 1).** The operation record, the plan of operations (the manifest),
   the preview rendered from it, the run journal, resume, the credential guard, the provider
   interface with fake providers, and the vault and machine gate.
2. **Sunrise, the local half (slice 2).** The new repo and its doc kit, staged-document adoption,
   the vault entry, memory and the terminal shortcut, as operations.
3. **The providers (slice 3).** GitHub, Vercel, Supabase through the Vercel Marketplace, and the
   provider-blind database backup, each behind the frame's interface, each with a fake.
4. **Sunset and restore (slice 4).** Retirement as operations whose default leans on no expiry
   window, and a restore that is a command (P16, as reworded by the owner's word in A6; where a
   restore gets its plan is the frame's EV-5 and EV-7).
5. **The join (slice 5).** One throwaway project taken through sunrise, sunset and restore on the
   real services with the owner present (P12), install proofs on both harnesses, marketplace
   entries, README counts, guide findings, the full outside review.

Out of scope: Notion on any layer (R3); any provider outside R4; cutover or retirement of the v1
`sun` plugin (P14; E17 to E19); any change to `plugins/records/`, `plugins/readers/` or the ten v2
cores (E16-2); the carried E15 punch-list items (R6, E18's pre-release round); the OpenCode
adapters; a third harness.

**Measured in v1 on `5cf37d5`, for the picks.** Notion is named on 26 lines of sunrise and 15 of
sunset. Every one of the 7 lines of sunset that names the Trash names Notion's (the board is
"moved to trash, restorable ~30 days"); with Notion out, no v1 step leans on a Trash window, and
what remains of that class is each provider's own retention clock on a paused resource (section
16; the catalog's Part 6, M3). Neon is named on 4 lines of each skill. "npm publish" is a column of sunrise's
project-type table and no phase publishes anything. v1 passes the database connection string to
`pg_dump` as an argument and the Vercel token to `curl` in a header argument: both are visible in
the process table while the command runs (the frame's SEC-2 and SEC-3 close both).

## 3. Boundaries every slice keeps

- One writer per worktree. A builder writes only under the folders its slice names (section 13) and
  the scratch directory it is given. Never `plugins/records/`, `plugins/readers/`, any of the ten
  v2 cores, any v1 plugin folder (`plugins/sun/` included), `.claude-plugin/marketplace.json` (the
  control room adds entries at close), `docs/feedback.md` or `docs/ideas.md`.
- A builder never runs `git add`, `commit`, `stash`, `checkout`, `reset`, `merge`, `worktree`,
  `branch`, or any git command that changes a worktree, its index or its branches. `status`, `log`,
  `diff`, `rev-parse`, `show`, `archive` to a temporary directory are fine. Git commands inside a
  test's own temporary repository are the test's. The control room checks every round and makes
  every commit.
- **No real service in slices 1 to 4.** No builder, test, proof or reviewer run calls a real `gh`,
  `vercel`, `supabase`, `psql` or `pg_dump` against an account, opens a real credentials store, or
  touches the real vault, the real memory stores, the real shortcut file, a real crontab or a real
  LaunchAgents folder. Every provider is its fake (E16-8); every machine location is a path under
  the test's temporary directory, reached through the one place the core resolves it (E16-12).
  The only real-service run of this step is slice 5, with the owner present.
- Runtime floor: `/usr/bin/python3` 3.9.6 and git 2.50.1. Python 3.9 syntax. Standard library
  only, with the one declared exception, `jsonschema==4.25.1` through `uv run` (PEP 723); a script
  started without it exits 3 with a plain message. `--help` and argument checks work without it.
- No network in any test. No MCP tool. No model call inside any script. A core's script never
  launches a harness and never invokes another skill.
- Tests build their fixtures in a temporary directory and clean up (`PYTHONDONTWRITEBYTECODE=1`; no
  `__pycache__` left). Install probes run only in isolated homes. Suites are written so their
  modules run side by side from the first slice (P4).
- The repository is public. Fixtures are synthetic: no text copied from another repository, no
  personal, legal or financial content, no personal paths, no machine names, no account names, no
  key-shaped strings (a planted test secret is a marked canary built at run time, never a literal
  in a committed file that a scanner would read as a key).
- Test first for every behavior a check of section 12 or a required test names: the failing output
  is recorded before the code that makes it pass.
- No em dashes in anything written for this step, except inside a v1 form copied byte for byte
  where the form is ruled load-bearing (E16-13 names them).

## 6. Rulings of this contract

- **E16-1, behavior is kept, the mechanics move.** Sunrise keeps: the vault gate first; never
  clobber; preview before executing and an explicit go (how: the frame's RUN-8, RUN-9); ask what the project is and use his words;
  layers conditional on the project type; end verified (the push landed, the clean production
  address answers 200, the pulled env file holds its keys, the kit check passes); the cross-links
  written on day one; resumable (how: the frame's RUN-10, RUN-11, OP-5 to OP-7). Sunset keeps: the vault gate first; never delete; preview and an
  explicit go (how: the frame's RUN-8, RUN-9); ask the reason and use his words; cancel active automation; copy the project's own
  memory store before the repo moves, into the folder beside it (A2) (how: the frame's ORD-4, KEEP-3); back the database up before idling it and never drop
  it (how: the frame's KEEP-1 to KEEP-3); never move or archive a repo with uncommitted or unpushed work without surfacing it; the
  loose ends surfaced and never acted on. What moves is where the deterministic half lives (a
  script, not prose). What leaves is Notion (R3) and whatever the picks cut. A proposed change to
  any other decision is the owner's ruling and lands in section 18.
- **E16-2, frozen folders.** At close, `git diff --stat <branch point> -- plugins/records
  plugins/readers plugins/sun` and the same for the ten v2 core folders print nothing. A need those
  components do not meet is a numbered question and a stop on that point.
- **E16-3, the operation is the unit.** What one operation is, and what counts as its one change,
  is the frame's (`2026-10-12-stations-e16-frame.md`, OP-1, OP-2). A change that is not a row of the
  approved manifest does not happen (the frame's RUN-9). The frame
  document is the single source for the frame, and each lane's own rows for its operations; this
  contract restates neither (A5).
- **E16-4, the owner approves what he read, and nothing else is done.** The preview shows him every
  operation the run may make; nothing he was not shown is done after his go; and the plan he
  approved is never changed, a different plan needing a new preview and a new go. Each remote row is
  shown with the account it acts as, and a step only the owner can take is shown to him and never
  attempted by the script. How the preview, the go and the plan are bound together is the frame's
  (RUN-5, RUN-8, RUN-9, RUN-11, OP-9).
  This is the plan's "authorization named in their preview".
- **E16-5, a run keeps its record, and one run at a time works on a project.** The record is in the
  private folder the owner ruled (A2), outside every repository. How it is written, and how runs are
  kept apart, is the frame's (LOG-1, LOG-2, RUN-2 to RUN-4).
- **E16-6, resume.** A run that was killed or stopped can be gone on with. No effect is applied
  twice, and the tool never claims as its own what it cannot prove it did (A5); how it decides, and
  what may be made again without being an effect, is the frame's (OP-5 to OP-8, EV-1, EV-3). A kill at any
  point of any operation leaves a state a rerun completes or stops on plainly; the
  kill sweep of section 12 shows it for every row of every provider's fake.
- **E16-7, credentials never leave their channel** (the frame's SEC-1 to SEC-12). The tests show it
  on the success path and on
  every failure path (plan A8: "tests the tracing and error-output paths for credential
  exposure"); what they plant and where they look is the frame's SEC-11.
- **E16-8, providers sit behind one interface, each with a fake.** A provider module offers what
  the frame requires of one (its ROW-1, SEC-3 and SEC-4) and an identity read (its RUN-5); how the
  real one reaches its provider is the frame's (SEC-2, SEC-3). A fake is a program the
  tests put first on the path (the fake harness stays in this contract as a named exception, by the
  owner's word, A6): it keeps its state in a file, records every call's arguments and the
  names of the environment variables it was given, can be told to fail, to hang, to answer late and
  to echo a secret into its error text, and it can be killed mid-call. What v1 reached through a
  harness connector (the Vercel project list) the core reaches through the tool, never through a
  connector (a connector is not a declared command; the frame's SEC-3).
- **E16-9, declared git behavior.** Every git command that changes a repository or a remote is
  declared before the go, and none that was not declared is run (how, and how it is tested: the
  frame's OP-11; each lane's own list). D6 is read narrowly (the control room's proposal, with no typed word of the owner's; A6): sunrise pushes the initial scaffold to
  `main` of a repository this run created and whose remote holds no commit, once (the lane's push

  the real services force a tracked change after that push, the run stops for the owner (catalog
  Part 6, M1). Sunset's remote changes are a dated tag and the archive. No other push, and no push
  to `main` of a repository that already has history.
- **E16-10, sunset never deletes and its default leans on no clock** (A1, P11). Every record
  sunset undertakes to preserve is preserved and checked before anything is moved, removed or
  paused (in what order, and how it is checked again: the frame's ORD-4 and KEEP-1 to KEEP-3; the
  lane's rows); the tombstone
  names each provider clock that still runs (the lane's forms; the catalog's Part 6, M3).
- **E16-11, a way back is claimed only on proof** (A5), and restore is a run of its own, never
  sunset backwards (A1, P16; A6). What must be on record for a way back, and when, is the frame's

- **E16-12, the gate and the machine's facts.** The vault and machine gate keeps v1's
  four checks; it comes before anything else, the cue included, and a failed gate creates nothing

  Every machine location (the developer root, the archive folder, the vault, the staging folder,

  probe or from one user-level settings file outside any repository, and is overridable for tests

  No committed file holds a personal path or an account name.
- **E16-13, the executor decides, the script records.** A script does the deterministic work, by

  for the owner, and never runs a scaffolder that was not a row he approved. The forms are v1's
  with exactly the changes the lane's list of form changes holds, the frame's lines among them
  (FORM-1 to FORM-3; the catalog's Part 5 is the draft of that list); any other change to a form is a stop.
- **E16-14, the harness seams are named.** What v1 did with a Claude Code tool or a model call

  listing and cancelling scheduled routines, the two Claude memory stores, the kit check's canary

  summary, never passed silently.
- **E16-15, versions and interface.** The new plugin starts at `0.1.0` with `interface_version` 1
  in every CLI response. Every CLI follows the A7a helper interface (plan A8; the CLI interface
  stays in this contract as a named exception, by the owner's word, A6): `--help` with
  arguments, defaults, an example and side effects; JSON on standard output and nothing else;
  diagnostics on standard error; exit 0, 2, 3, 4, 10 and 1 with their A7a meanings; safe reruns;
  partial effects named in `--help`.
- **E16-16, no implicit import of v1.** A test in the new core fails on a path under `plugins/sun/`,
  on any deference to a v1 skill's text and on any subprocess whose arguments name a v1 skill. The
  shared cue assets are copied into the new plugin, not reached across.
- **E16-17, the frame freezes when slice 1 closes.** A lane that needs a frame change stops and
