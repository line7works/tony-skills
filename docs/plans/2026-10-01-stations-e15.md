## 1. What E15 delivers

Plan text, verbatim. **E15. Rebuild vertical, handoff, and ship integration.** **Artifact:**
Whole-build review, cross-harness handoff, and a coordinator that calls only qualified v2
stations. **Done when:** Vertical checks the correct base and source scope; reviewer packets
exclude prior verdicts and author advocacy where independence requires it; handoff reconstructs
state from durable records; ship respects failure and approval boundaries. A trace demonstrates
that no v1 back-half station is called indirectly. **Runs:** X + S, reviewed through qualified v2
signoff with R. **Dependencies:** E13 to E14. **Owner gate:** D5 for changed summons; D4 for
changed review policy.

The plan's lanes table: "E15 vertical, handoff, ship | One lane after E13 and E14 | Composes the
others." No plan amendment (A1 to A12) names E15.

**Runs, read under plan ruling R1** (Tony, 2026-09-13: "The native LLM builds for itself and then
has an outside LLM review it"), as E13 and E14 read it: the shared core, the Claude adapter and
the Codex adapter built by Claude builders in the control room (P0, P3), R the outside reviewer
(Astra, GPT-6, through `codex exec` on a sealed copy, P1). "Through qualified v2 signoff" is read
as E14 read it: the review follows `signoff-v2`'s contract (independence, evidence, severity to
verdict), run through the Astra kit, because `signoff-v2`'s own reviewer floor (Opus-class)
classes no GPT row.

D5: "Invocation interface. Retain current explicit natural-language summons as well as commands;
or move selected stations to command-only invocation. Recommended: retain existing accepted
summons; implement equivalent native controls where possible. Applies only to
invocation-changing portions of E14 to E15."

D4: "Production review policy. Preserve existing reviewer eligibility/counts and test
requirements; or replace selected rules with task-qualified eligibility and evidence-based review
depth. Recommended: preserve current requirements during the pilot. Change individual policies
only after comparative evidence."

In plain words: four things get built.

1. **The back frame (slice 1, first).** The helpers the three new cores share, copied from the E14
   frame byte for byte (ruling E15-3), plus the one new shared piece: the station trace (E15-7).
2. **A portable vertical core (slice 1).** The whole-build review: the gate, the base and the
   source scope computed by script, the cold packets built by script with prior verdicts and author
   advocacy left out (E15-8), the local fleet first, the outside fleet on the owner's word, every
   outside finding verified, one verdict doc.
3. **A portable handoff core (slice 1).** The end-of-slice photograph, rebuilt from the records
   component and git read now, never from the session's memory: the question gate, the dated
   ledger lines through the records component, one additive block, the next move, the pointer.
4. **A portable ship core (slice 2).** The coordinator: one slice through `build-v2`, `signoff-v2`,
   the fixes, `recheck-v2`, at most one extra lap, the four stops and the pauses, calling only v2
   stations and proving it with a trace.

Then the join (slice 3): install proofs on both harnesses, the stations proof widened to ten,
marketplace entries, README counts, guide findings, the full outside review.

Out of scope: sunrise and sunset (E16); cutover or retirement of any v1 skill (P7; E17 to E19); any
change to `plugins/records/` (E15-2); any change to what `build-v2`, `signoff-v2`, `recheck-v2` or
the four front cores decide (E15-2); the Python-startup class under Codex (PARKED, section 5); the
OpenCode adapters; live model trials as a suite; a third harness.

## 3. Boundaries every slice keeps

- One writer per worktree. A builder writes only under the folders its slice names (section 13) and
  the scratch directory it is given. Never `plugins/records/`, `plugins/readers/` (unless P9 places
  item 4(c), in the files the brief names), `plugins/build-v2/`, `plugins/signoff-v2/`,
  `plugins/recheck-v2/`, the four front cores, any v1 plugin folder, `.claude-plugin/marketplace.json`
  (the control room adds entries at close), `docs/feedback.md` or `docs/ideas.md`.
- A builder or checker never runs `git add`, `commit`, `stash`, `checkout`, `reset`, `merge`,
  `worktree`, `branch`, or any git command that changes a worktree, its index or its branches.
  `status`, `log`, `diff`, `rev-parse`, `show`, `archive` to a temporary directory are fine. The
  control room checks every round and makes every commit.
- Runtime floor: `/usr/bin/python3` 3.9.6 and git 2.50.1. Python 3.9 syntax. Standard library
  only, with the one declared exception, `jsonschema==4.25.1` through `uv run` (PEP 723); a script
  started without it exits 3 with the frame's message. `--help` and argument checks work without it.
  Guarded entries start through `setups/safe-python.sh` (E14 A15).
- No network. No MCP tool. No model call inside any script. A core's script never launches a
  harness, never summons a reader, never invokes another station and never publishes; the skill body
  directs the executor to summon (through `readers`) or to visit a station, and a test never does.
- A station reaches the records component through the resolver snippet and the CLI only. It never
  opens a log file, never imports `records_core`, and confirms `interface_version` 2 through
  `component-identity`, stopping with exit 3 and a plain message when the component is missing or
  speaks another version.
- A core never reads a v1 skill's files at run time, never shells to one, and never defers to one as
  law (E15-6). A v2 sibling (a station ship visits, the code book vertical restates) is resolved the
  records way (route 3a, then 3b), never by a personal path.
- Tests build their fixtures in a temporary directory and clean up (`PYTHONDONTWRITEBYTECODE=1`; no
  `__pycache__` left). Install probes run only in isolated homes.
- The repository is public. Fixtures are synthetic: no text copied from another repository, no
  personal, legal or financial content, no personal paths, no machine names, no key-shaped strings.
- Test first for every behavior a seeded case or a required test names: the failing output is
  recorded before the code that makes it pass.
- No em dashes in anything written for this step, except inside a load-bearing v1 form copied byte
  for byte (E15-11), where the form wins and the exception is named in the core's contract.

- **E15-1, behavior is kept, the mechanics move.** No core changes what its v1 station decides.
  Vertical: the gate (every slice `signed off`, the two preconditions, the collapse only by the
  owner's invocation words), the ask every run, the base precedence, the tracked-files-only export,

  the deterministic half lives (a script, not prose) and how a station is reached (a v2 sibling with
  a trace, E15-7). A proposed change to any decision is the owner's ruling and lands in section 18.
- **E15-2, frozen folders.** At close, `git diff --stat <branch point> -- plugins/records
  plugins/build-v2 plugins/signoff-v2 plugins/recheck-v2 plugins/precon-v2 plugins/architect-v2

  stops on that point.
- **E15-3, the back frame is a copy, not a fork.** The three new cores reuse the E14 helpers they
  need, copied byte for byte from `precon-v2`'s canonical copies, and list them in their own
  `references/back-files.txt`; `tests/test_back_equal.py` in each new core compares every listed file
  with `precon-v2`'s copy (skipped, never passed, in the installed shape) and with the other two new

  front four's. Files that are new and shared by the three (the trace, section 7) have `vertical-v2`
