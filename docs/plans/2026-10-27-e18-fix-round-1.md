# E18 fix round 1: signoff-v2 records a kept note honestly (build plan, 2026-10-27)

Intent: the first live one-command run (ship run ship-a-20261027-fb9c, on `docs/plans/2026-10-26-e18-live-run.md`) built its slice and its fresh signoff session signed it off, but the run stopped `visit-unfinished` on two signoff-v2 defects. This round fixes those two, bumps the two plugins whose files changed since the reinstall, and nothing else. Then a second live run.

Source: the live run's report and signoff-v2 SKILL NOTEs from E18 Slice D's two signoff runs (PR #120). The owner's word: "fix round" (2026-10-27).

The defects:

1. A kept note breaks the result. `signoff_core/answer.py` `adjudicate` copies each `notes_kept` entry into the result's `notes` as the reviewer wrote it. `answer.schema.json` lets a kept note's `severity` be null; `result.schema.json` gives `notes` the `finding` shape, whose `severity` must be BLOCKER, MAJOR or MINOR. So `record` writes a result its own schema refuses and exits 4. And the check that runs before any project-record write (`signoff.py` `cmd_record`, Astra's F16) runs only the semantic validator, not the schema, so the verdict doc, the records events and the card all land first: the records say signed off while the run says stopped.
2. A late quotation looks withheld. `signoff.py` `provenance_of` reads the delivered packet through `signoff_core/packet.py` `read_text_or_none`, which stops at `MAX_DELIVERED_BYTES` (512 KiB, a per-file delivery cap). A packet larger than that (Slice D's was 862 KB and 949 KB) is cut, so a reviewer quoting the back of the packet is refused on independence as if the words came only from the builder's withheld notes.

Constraints:

- signoff-v2's independence rule does not change (AGENTS.md invariants): the provenance check still refuses a quotation found only in withheld text. Slice B only stops a delivered quotation from looking withheld.
- Never rewrite stored history: earlier verdict docs, records, run directories, plans, `RESULTS.md` files, setups records and measured counts stay as they are, including the live run's records committed as `34a2165`.
- A file several stations carry byte for byte stays byte for byte equal across every copy. Neither fix touches a copied file; a builder who finds one must change stops and asks.
- Each check is one line, `<name>: <command>`, the command run from the repository root and reported under exactly that text (build-v2 matches it). The name holds no colon.
- The two signoff-v2 adapter suites run alone, never beside another suite (their helper starts a nested `uv run` that breaks under contention). Other suites may run up to four side by side, each a different suite, each with its own output file.
- No push, no PR, no merge: the owner's word only.

## Slice A - a kept note never breaks the result

Status: not started

Requirements:

- A result's `notes` entry may carry a null `severity`: `result.schema.json` gives `notes` its own shape, the same as `finding` except that `severity` is BLOCKER, MAJOR, MINOR or null. `findings` (what was raised) keeps a required severity. A kept note's other fields are recorded as the reviewer wrote them; the answer is never edited.
- The check before any project-record write runs the result schema as well as the semantic validator on the proposed completion. A proposed result that fails either stops the run with nothing recorded (no verdict doc, no records event, no card move), naming the schema error.
- The chat block and any other rendering of a note with a null severity print it without a severity rather than failing or printing "None".
- No other change.
