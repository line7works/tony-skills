# E17 fix round 1: one suite run per review, one lens per reviewer (build plan, 2026-10-24)

Intent: signoff-v2's review of the E17 canary took about 10 hours. Two station faults made it that long. Every reviewer ran the repository's full suite on its own (about 3 hours each) beside the session's own run of it (canary finding C-12). And the five DEEP lenses got byte-identical mandates, each listing all five lenses, so the run paid for five full reviews instead of one review split five ways (C-7). This plan fixes those two, and nothing else.

Source: the E17 canary's findings C-12 and C-7, recorded in the control room's notes on 2026-10-22, and the canary signoff's run (`astra-outputs/e17/canary/signoff-run` in the clerk repo). The owner asked for the speed-up ("Running one at a time took almost 12 hours. We need to speed that up.") and gave the go for this plan ("Go").

Constraints:

- The repo is public: no secrets, personal paths, mail addresses, key-shaped strings or em dashes in any file.
- Never rewrite stored history: earlier verdict docs, records and run directories stay as they are.
- The independence rules, the evidence rules, the anti-rubber-stamp rule and the recording transaction do not change. A clean review still lists its executed checks (Step 4, rule 3).
- Core tests run as `cd plugins/signoff-v2/skills/signoff-v2/scripts/tests && uv run --python /usr/bin/python3 --with jsonschema==4.25.1 python3 -m unittest discover -s . -p '<module>.py'`. Adapter tests run the same way from `plugins/signoff-v2/skills/signoff-v2/adapters/<harness>/tests`.
- No push, no PR, no merge: the owner's word only.

## Slice A - one full suite run per review

Status: not started

Requirements:

- The reviewer's mandate (`mandate_text` in `plugins/signoff-v2/skills/signoff-v2/scripts/signoff.py`) tells each reviewer that the reviewing session runs the repository's full test command once for this review, and that the reviewer does not run the full suite or any long-running sweep itself. A reviewer runs the narrowest command that proves or refutes its finding: one test module, one test, or a probe it writes in its own scratch directory. It lists each one under its executed checks as it does today.
- A reviewer that believes a finding can only be shown by the full suite says so in its report, naming the command, instead of running it.
- SKILL.md Step 3.5 says the session runs the project's full test command once per review, and that this is the only full run in the review: the reviewers do not run it. The contract (`references/signoff-contract.md`) says the same where it describes the mandate and the execute step.
- Nothing else in the mandate changes.

Checks:

- A new test, red before the change: a `request` run's mandate holds the one-full-run rule and the narrowest-command rule.
- The full signoff-v2 core suite and both adapters' test suites pass.

## Slice B - one lens per reviewer

Status: not started

Requirements:

- `request` writes one mandate per lens in the review's lens set, beside the existing `readers/mandate.md`. Each names only its own lens, with what that lens looks for (the lens descriptions in SKILL.md Step 3), and names the review's other lenses as covered by sibling reviewers. A reviewer still reports anything it finds outside its lens; it does not go looking there.
- Every part of the mandate other than the lens section is the same in each lens's mandate as in `readers/mandate.md`: the packet, what is not evidence, the finding shape, read-only, the sheet, and Slice A's suite rule.
- `request.json` names each lens's mandate. Each adapter's request mode (`adapters/claude-code/reviewer.py`, `adapters/codex/reviewer.py`) binds each `--lens` block to that lens's own mandate, and refuses a lens that is not in the run's lens set. With no `--lens`, the single block keeps `readers/mandate.md`, as today.
- LIGHT's one fused reviewer gets one mandate naming both of its lenses.
- SKILL.md Step 3 and the contract say each lens's reviewer receives its own lens's mandate.

Checks:

- A new core test, red before the change: a DEEP run's `request` writes five lens mandates whose lens sections differ pairwise, each naming only its own lens as its mandate, and whose other sections equal `readers/mandate.md`'s.
- A new test in each adapter, red before the change: request mode with five `--lens` flags gives five blocks, each bound to its own lens's mandate; an unknown lens is refused; no `--lens` still binds `readers/mandate.md`.
- The full signoff-v2 core suite and both adapters' test suites pass.
